**** Understanding MCP with a Simple Example

***** What is MCP?

MCP (Model Context Protocol) lets LLMs *call tools* on your machine. You write a server that exposes tools, the LLM decides when to call them, and results flow back into the conversation.

***** 1. A Simple MCP Server

Let's build a *file-stats* server that exposes two tools:
- =word_count= — count words/lines/chars in a file
- =list_directory= — list files in a directory

Create =~/.config/mcp/file_stats_server.py=:

#+begin_src python :tangle /.config/mcp/file_stats_server.py
#!/usr/bin/env python3
"""A simple MCP server that provides file-system utilities."""

import os
import json
import sys

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("file-stats")


@mcp.tool()
def word_count(filepath: str) -> str:
    """Count words, lines, and characters in a file.

    Args:
        filepath: Absolute path to the file to analyze.
    """
    try:
        with open(os.path.expanduser(filepath), "r") as f:
            content = f.read()
        lines = content.count("\n")
        words = len(content.split())
        chars = len(content)
        return json.dumps({"lines": lines, "words": words, "chars": chars, "filepath": filepath})
    except Exception as e:
        return json.dumps({"error": str(e)})


@mcp.tool()
def list_directory(dirpath: str) -> str:
    """List files and subdirectories in a directory.

    Args:
        dirpath: Absolute path to the directory.
    """
    try:
        dirpath = os.path.expanduser(dirpath)
        entries = []
        for entry in sorted(os.listdir(dirpath)):
            full = os.path.join(dirpath, entry)
            entries.append({
                "name": entry,
                "type": "dir" if os.path.isdir(full) else "file",
                "size": os.path.getsize(full) if os.path.isfile(full) else None,
            })
        return json.dumps(entries, indent=2)
    except Exception as e:
        return json.dumps({"error": str(e)})


if __name__ == "__main__":
    mcp.run(transport="stdio")

***** 3. How to Use It

****** Verify the server is running

#+begin_src
M-x mcp-hub
#+end_src

You should see =file-stats= listed with status *running* and its two tools registered.

****** Use it in gptel

1. *Open a gptel buffer*: =M-x gptel= (or however you launch it)
2. *Activate the MCP tools*: Press =C-c m= (=gptel-mcp-dispatch=) — this shows available MCP tools. *Enable* the =file-stats= tools (toggle them on).
3. *Ask a question that needs the tools*:

#+begin_src
How many words are in my init.el? The file is at ~/.emacs.d/init.el
#+end_src

****** What happens behind the scenes

#+begin_src
┌─────────┐    prompt     ┌─────────┐   stdio/JSON    ┌──────────────┐
│  You in  │ ──────────── │  LLM    │ ───────────────▶│ file_stats   │
│  gptel   │              │ (GPT/   │ ◀───────────────│ MCP server   │
│  buffer  │ ◀─────────── │ Claude) │   tool result   │ (Python)     │
└─────────┘   response    └─────────┘                 └──────────────┘
#+end_src

1. Your prompt + tool schemas are sent to the LLM.
2. The LLM decides to call =word_count= with ={"filepath": "~/.emacs.d/init.el"}=.
3. =gptel-mcp= intercepts the tool call, routes it through =mcp.el= to your Python server via stdio.
4. The server runs the function, returns JSON.
5. The result is fed back to the LLM, which formulates a human-readable answer.

****** Key points

- *You never call tools manually* — the LLM decides based on your prompt.
- *=C-c m=* is how you control which tools are available to the LLM for the current buffer.
- *=mcp-hub=* is your dashboard — restart/stop servers, see registered tools.
- Tools must have good *docstrings* and *typed arguments* — that's what the LLM reads to decide how to call them.
